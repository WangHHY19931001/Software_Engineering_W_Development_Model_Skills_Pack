## 2. 前置分解：48 条反模式的失败类型（盲分类 + 交叉验证）

在做行为实验前先做一次**成本更低、结论更稳**的分解：若多数反模式属 discipline 型，则按 P1 它们**本就该用禁令**，全量改写会在规则层面自相矛盾。

我按"动机"口径快速初判得 discipline ≈ 29/48（60%）。随后派一个**未受我判断影响的独立代理**按"**症状**"口径盲分类（其判定口径自行声明为：必需物不存在→omission；做了不该做的动作→discipline；产出了但形态错→shape；该按条件却写成无条件→conditional）。独立结果为：

| 分类 | 独立盲判（症状口径） | 我的初判（动机口径） |
| --- | --- | --- |
| discipline | **12**（#3,4,6,7,8,9,10,12,13,15,45,48） | ≈29 |
| shape | **14** | ≈10 |
| omission | **21** | ≈9 |
| conditional | **1**（#41） | ≈0 |

**两口径的差异集中在"跳过类"条目族**（#1/#11/#18/#19/#21/#33/#39/#42/#44 等）：按**症状**是"缺了一个环节"→ omission；按**动机**是"主动跳过"→ discipline。独立代理自己也把这个分叉点列为其最大不确定性（它列了 12 条拿不准确认项并给出双候选）。

**该分歧不影响 D-1 的结论方向**——这正是本次分解的价值所在：

- 按**症状口径**：discipline 仍占 12/48（25%）→ 对它们改用正向 recipe 违反 P1；
- 按**动机口径**：discipline 占 29/48（60%）→ 违反面更大。

**即：任一合理口径下，"对全部 48 条统一改成正向表述"都会被 P1 自身否证。** 这是一个口径稳健（robust to both readings）的结论。

## 3. 行为实验设计

**SUT**：一份可自包含完成的产出任务（不依赖本仓库内容，避免规则文本泄漏）：

> 为下述功能产出 2–3 张"垂直切片"票据，作为 `tickets.md` 的内容。功能：给一个命令行工具增加 `--dry-run` 选项，开启后先在真正写入状态文件前打印将要执行的变更并以退出码 0 结束；若状态文件不存在则以退出码 1 结束并打印原因。已知已有原子写入函数（临时文件 + rename）与运行日志校验函数；状态文件为 JSON，路径由调用方传入；TypeScript + vitest。每张票据说明"要做什么、如何验证"。

**三臂**（仅"补充要求"不同，其余逐字相同；每个 rep 为独立全新上下文）：

| 臂 | 补充要求（逐字） |
| --- | --- |
| **A 禁令**（W-model 现形态） | `不要在票据中出现具体的文件路径、行号或代码片段。` |
| **B 正向 recipe**（P1 为 shape 型推荐的形式） | ``每张票据必须且仅包含三段：① `行为契约` —— 用可观察行为描述（不使用文件引用）；② `符号契约` —— 涉及的符号名与类型签名；③ `验证` —— 一条可执行命令加预期结果。`` |
| **C 对照**（S04 要求的 no-guidance control） | （无） |

**指标**（确定性正则，不依赖人读）：`unwanted = 路径token数 + 行号引用数 + 2×代码块数 + 内联代码数`。
**n**：每臂 5 次独立重复，共 15 次。

## 5. 结论（分三层，不得混同）

### 5.1 本次实验**无效裁定 P2**——因为我的实验设计有致命混淆

**B 臂的 recipe 明确要求 "`符号契约` —— 涉及的符号名与类型签名"，而我的指标恰恰惩罚"代码式内容"（代码块 + 内联代码占分）。** 即：**treatment 与 metric 相互构造冲突**——B 越忠实执行被指定的形态，得分就越差。B 的 `三位标签 3/3` 证明它确实照做了，而照做必然引入类型签名。

因此 mean(B)=13.2 **不是"recipe 更差"的证据，而是我的指标测错了对象**（它测的是"技术内容密度"，不是"不该有的内容"）。

**本实验不能支持 P2，也不能反驳 P2。P2 全局状态仍为 🟡。**

### 5.2 但实验产出了一条**有效且决定性**的观察：对照臂未失败

按 S04（本次已采纳）的原文规则：**"If the control doesn't exhibit the failure, there is nothing to fix — stop, don't author the guidance."**

- **C 对照臂 5 次中有 2 次产出为零不该有内容，均值仅 3.6/15，最大 7。**
- 即：**在本 SUT 上，不给任何指引也不会明显出问题** → 按 S04，**不存在需要修复的缺陷，因此不应编写该指引**。

这条不是"P2 被推翻"，而是**S04 的适用前提被证伪**：本场景没有可复现的失败可供消除。这是本次实验最有价值的产出。

### 5.3 对 D-1 的裁定影响

D-1 原推荐"**否——不全量改写**"，理由原为"支撑证据未随仓"。现在理由升级为**三条独立且相互加强的依据**：

1. **规则自洽**（§2）：任一合理分类口径下，全量改写都会对 12–29 条 discipline 型条目用错形式，违反 P1 自身；
2. **无可修缺陷**（§5.2）：对照臂未复现失败 → 按 S04 不应编写该指引；
3. **证据缺失**（§5.1）：P2 的量化支撑未被本地复现，原报告亦无随仓证据。

**⇒ D-1 的"否"维持，且该残留项就此关闭**：不是"等 A/B 出证据再定"，而是"**A/B 已执行，其结论支持不做**"。

## 7. 代表样本摘录

**A 中位样本（A1，score 0）**——禁令臂：无路径、无代码块：

```
# 票据：命令行工具新增 `--dry-run` 选项
## 票据 1：dry-run 预览并成功退出（快乐路径切片）
### 这张票据要做什么
打通 `--dry-run` 的最短端到端链路，让用户第一次能"看到将要发生什么而不真的发生"：
- 命令行入口识别并解析 `--dry-run` 开关；关闭时行为与现状完全一致，不引入任何回归。
- 为"将要写入状态文件的变更"建立统一的描述收集机制：每条计划中的变更都产出人类可读的一行说明（涉及哪个状态文件、将发生写入还是更新）。
- 开启 `--dry-run` 时，在触碰真实写入之前先输出全部计划变更，然后以退出码 0 结束。
```

## 票据 1：缺失状态文件的预检（退出码 1 路径）

### 符号契约        ← 该段按提示词要求产出「符号名与类型签名」，直接抬升本臂的代码类计数
（…类型签名…）
