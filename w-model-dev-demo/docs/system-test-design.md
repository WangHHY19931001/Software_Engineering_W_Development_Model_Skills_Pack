## §2 性能测试（TC-PERF）

> 对应 NFR-001 P95 < 200ms / NFR-004 单表 ≥ 10000 条。

### TC-PERF-001 API 响应时间 P95 基线

- **场景**：所有读 API（GET /api/articles、GET /api/articles/:id、GET /api/articles/:id/comments、GET /api/search、GET /api/articles/archive）在 1000 条数据量下并发 100 QPS 持续 10min。
- **输入**：预置 1000 篇已发布文章 + 100 用户；并发 100 QPS。
- **预期输出**：P95 < 200ms；P99 < 500ms；错误率 < 0.1%。
- **优先级**：高（TC-DES-008 性能基线）

### TC-PERF-002 写 API 响应时间基线

- **场景**：写 API（POST /api/articles、POST /api/articles/:id/comments、POST /api/articles/:id/like）在 1000 条数据量下并发 50 QPS 持续 5min。
- **输入**：预置数据 + 鉴权 token + 50 QPS。
- **预期输出**：P95 < 200ms（含 bcrypt 哈希场景 P95 < 500ms 可接受）；错误率 < 0.1%。
- **优先级**：高

### TC-PERF-003 单表容量 10000 条压力

- **场景**：单表预置 10000 篇文章，执行列表查询 + 搜索 + 归档查询。
- **输入**：10000 篇文章；单次查询。
- **预期输出**：P95 < 500ms（容量上限场景放宽）；不发生 OOM；查询结果正确。
- **优先级**：高（NFR-004）

### TC-PERF-004 RSS 订阅响应时间

- **场景**：GET /api/rss 在 1000 篇已发布文章场景下响应时间。
- **输入**：1000 篇已发布文章。
- **预期输出**：P95 < 300ms（XML 渲染）；Content-Type: application/atom+xml。
- **优先级**：中

## §3 可靠性测试（TC-REL）

> 对应 NFR-003 错误处理 100% 统一格式。

### TC-REL-001 统一错误响应格式

- **场景**：触发各类错误（400/401/403/404/409/429/500），校验响应格式统一。
- **输入**：构造 7 类错误请求各 1 个。
- **预期输出**：所有错误响应格式 `{error: {code, message, details?}}`；HTTP 状态码与 code 一致。
- **优先级**：高

### TC-REL-002 未捕获异常兜底

- **场景**：模拟 Service 层抛出未捕获异常（如 Map.get 返回 undefined 后访问属性）。
- **输入**：构造特定 ID 触发内部异常。
- **预期输出**：ErrorHandler 中间件兜底返回 500 `{error:{code:"INTERNAL_ERROR", message:"内部错误"}}`；不泄漏堆栈。
- **优先级**：高

### TC-REL-003 限流触发后恢复

- **场景**：用户超过 60 次/分钟后，等待 60s 后恢复访问。
- **输入**：连续 65 次请求 → 等待 60s → 再请求。
- **预期输出**：前 60 次 200；后续 429；60s 后恢复 200。
- **优先级**：中

## §4 内存测试（TC-MEM）

> 对应 NFR-004 单表 ≥ 10000 条。

### TC-MEM-001 容量上限边界

- **场景**：写入 10000 篇文章 + 10000 评论 + 1000 用户，监控内存占用。
- **输入**：批量写入数据。
- **预期输出**：内存占用 < 500MB；所有 API 正常响应；无 OOM。
- **优先级**：高

### TC-MEM-002 删除后内存释放

- **场景**：写入 10000 篇文章后删除 5000 篇，监控内存。
- **输入**：写入 + 删除。
- **预期输出**：内存占用下降（Map.delete 释放引用）；GC 后内存稳定。
- **优先级**：中

## §5 安全测试（TC-SEC）

> 对应 NFR-002 JWT 密钥 / NFR-005 zod 校验 / OWASP Top 10。TC-DES-009 安全基线。

### TC-SEC-001 JWT 密钥强度校验

- **场景**：启动时校验 JWT_SECRET 长度 ≥ 256 位（32 字节）。
- **输入**：分别设置 31 字节 / 32 字节 / 64 字节密钥启动。
- **预期输出**：< 32 字节启动失败并报错；≥ 32 字节正常启动。
- **优先级**：高

### TC-SEC-002 zod 输入校验覆盖率

- **场景**：所有 POST/PUT 接口提交非法 payload。
- **输入**：每个接口 1 个非法 payload（缺字段/类型错/超长/特殊字符）。
- **预期输出**：100% 返回 400 `{error:{code:"VALIDATION_ERROR", details:[...]}}`；不进入 Service 层。
- **优先级**：高

### TC-SEC-003 SQL 注入防御（虽为内存存储，校验输入净化）

- **场景**：在 title/content/comment 字段注入 `' OR 1=1 --` / `"; DROP TABLE--` 等payload。
- **输入**：注入 payload。
- **预期输出**：payload 作为字符串原样存储；不影响其他记录；查询正常。
- **优先级**：高（OWASP A03）

### TC-SEC-004 XSS 防御（RSS XML 转义）

- **场景**：在文章 title 注入 `<script>alert(1)</script>`，请求 RSS feed。
- **输入**：含 XSS payload 的文章。
- **预期输出**：RSS 输出中脚本被 XML 转义为 `&lt;script&gt;...`；浏览器不执行。
- **优先级**：高（OWASP A03）

### TC-SEC-005 越权访问防御

- **场景**：reader 角色尝试访问 admin/author 专属接口；author A 尝试修改 author B 的文章。
- **输入**：越权请求各 1 个。
- **预期输出**：reader 访问写接口返回 403；author A 修改 B 的文章返回 403。
- **优先级**：高（OWASP A01）

## §6 限流测试（TC-RL）

> 对应 NFR-006 每用户 60 次/分钟。

### TC-RL-001 单用户限流触发

- **场景**：单用户 1 分钟内连续 65 次请求同一接口。
- **输入**：65 次请求。
- **预期输出**：前 60 次 200；第 61-65 次 429 `{error:{code:"RATE_LIMIT_EXCEEDED"}}`；Retry-After 头存在。
- **优先级**：高

### TC-RL-002 多用户限流隔离

- **场景**：用户 A 触发限流后，用户 B 仍可正常访问。
- **输入**：A 65 次 + B 10 次。
- **预期输出**：A 第 61+ 次 429；B 全部 200。
- **优先级**：高

## §7 端到端业务流测试（TC-E2E）

> 对应 TC-DES-007 端到端流程。

### TC-E2E-001 完整创作流程

- **场景**：注册→登录→创建标签→创建分类→创建文章（草稿）→发布→评论→点赞→RSS 订阅。
- **输入**：顺序执行 8 个 API 调用。
- **预期输出**：每步返回预期状态码 + 数据；最终 RSS feed 含该文章；文章 likeCount=1。
- **优先级**：高

### TC-E2E-002 文章生命周期

- **场景**：创建（draft）→发布（published）→取消发布（draft）→更新→删除→评论级联删除。
- **输入**：状态转移 + 删除。
- **预期输出**：状态转移合法；删除后文章 404；关联评论同步删除（GET /api/articles/:id/comments 返回 404 或空）。
- **优先级**：高

### TC-E2E-003 密码重置全流程

- **场景**：注册→请求重置→使用令牌重置→新密码登录。
- **输入**：4 步 API 调用。
- **预期输出**：重置成功；旧密码登录失败（401）；新密码登录成功（200）。
- **优先级**：高

## §8 异常路径测试（TC-EXC）

### TC-EXC-001 不存在的资源

- **场景**：GET /api/articles/不存在的id、GET /api/articles/不存在/comments。
- **输入**：随机 UUID。
- **预期输出**：404 `{error:{code:"NOT_FOUND", message:"文章不存在"}}`。
- **优先级**：高

### TC-EXC-002 非法状态转移

- **场景**：对已发布的文章再次 publish；对草稿 unpublish。
- **输入**：非法状态转移请求。
- **预期输出**：400 `{error:{code:"INVALID_STATE_TRANSITION"}}`。
- **优先级**：高

### TC-EXC-003 重复注册

- **场景**：同一邮箱注册两次。
- **输入**：第二次注册。
- **预期输出**：409 `{error:{code:"EMAIL_EXISTS"}}`。
- **优先级**：高

### TC-EXC-004 令牌过期

- **场景**：使用过期 JWT 访问受保护接口。
- **输入**：过期 token。
- **预期输出**：401 `{error:{code:"TOKEN_EXPIRED"}}`。
- **优先级**：高

### TC-EXC-005 密码重置令牌复用

- **场景**：使用已使用的密码重置令牌再次重置。
- **输入**：已使用令牌。
- **预期输出**：410 `{error:{code:"TOKEN_USED"}}`。
- **优先级**：中

### TC-EXC-006 分类树成环检测

- **场景**：创建分类 A→B→C→A 形成环。
- **输入**：3 步 PUT 请求形成环。
- **预期输出**：第 3 步返回 400 `{error:{code:"CATEGORY_CYCLE_DETECTED"}}`。
- **优先级**：中
