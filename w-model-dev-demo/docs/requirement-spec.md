## 1. 项目概述

### 1.1 项目背景

基于现有 blog-system-demo（Express 4 + TypeScript 5 strict + 内存存储）扩展为多博主协作博客平台。本系统为 W 模型第 6 轮端到端调测的承载项目，验证 W 模型对扩展需求与多模块协作的处理能力。系统采用单实例内存存储架构，不引入数据库，依赖操作日志实现崩溃后重建。

### 1.2 项目目标

- 在现有 blog-system-demo 基础上扩展为支持多博主、多用户协作的博客平台
- 提供 13 个功能领域、5 类非功能特性、3 类约束的完整后端实现
- 满足 W 模型阶段 1 验收标准：需求规格 + 验收测试 + 风险评估 + RTM 登记齐备且可追溯
- 单元测试覆盖率 ≥ 80%（lines），接口 P95 ≤ 200ms（搜索 P95 ≤ 500ms）

### 1.3 范围

- 包含：站点管理、多博主、多用户、推荐、广告、统计、搜索、标签、分类、评论、通知、多博文、交叉引用等 13 个功能领域后端 API；JWT 认证、RBAC 权限、输入校验、审计日志等安全机制；性能、可用性、可测试性、可维护性等非功能特性
- 不包含：前端页面实现、移动端 App、第三方 OAuth 登录、数据库持久化（内存存储约束）、分布式部署（单实例约束）、邮件 SMTP 服务器自建（依赖外部 SMTP）

### 2.2 非功能需求

| 需求 ID | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-001 | 性能 | 接口响应 P95 ≤ 200ms（不含外部网络）、单实例并发支持 ≥ 100 QPS、搜索响应 P95 ≤ 500ms | P95 ≤ 200ms（通用）/ ≤ 500ms（搜索）；QPS ≥ 100；验收测试 UAT-041 在 100 QPS 负载下连续 60s 测得 P95 ≤ 200ms |
| NFR-002 | 可用性 | 内存存储崩溃后可从持久化日志重建（操作日志可选）、错误率 ≤ 0.1% | 错误率 ≤ 0.1%（每 1000 请求失败 ≤ 1）；验收测试 UAT-042 重放操作日志后状态与崩溃前一致 |
| NFR-003 | 安全 | JWT 认证 + bcrypt 密码哈希、角色权限分级（RBAC）、输入校验（zod schema）、防 SQL 注入（内存存储 N/A，但需防原型链污染）、敏感操作审计日志 | bcrypt cost ≥ 10；JWT 过期时间 ≤ 24h；zod 校验失败返回 400；原型链污染测试用例（`{"__proto__":{"isAdmin":true}}`）不污染对象；验收测试 UAT-043 + UAT-044 |
| NFR-004 | 可测试性 | 单元测试代码覆盖率 ≥ 80%（lines）、集成测试覆盖核心业务链路、系统测试覆盖端到端场景、验收测试覆盖所有功能点 | lines 覆盖率 ≥ 80%（vitest `--coverage`）；验收测试 UAT-045 校验覆盖率报告 ≥ 80% |
| NFR-005 | 可维护性 | TypeScript strict 模式 0 错误、模块化分层（controller→service→store）、公共工具复用（auth、validate、error-handler） | `tsc --noEmit` 退出码 0；模块分层目录结构存在；验收测试 UAT-046 校验 strict 编译通过 |
