## 3. 需求冲突登记

> 冲突对需用户在阶段门评审中决策。未决策前不进入阶段 2。

### CONFLICT-001：邮件通知「可选」语义模糊

| 字段 | 内容 |
|---|---|
| 冲突描述 | REQ-011 原文同时含「邮件通知（可选、关键事件邮件提醒）」，语义冲突：「可选」是指用户可在通知设置中关闭某类邮件，还是系统可以选择不实现邮件通知？ |
| 涉及需求 | REQ-0011 / NFR-003 / CON-001 |
| 影响范围 | 通知模块实现 / 第三方库依赖 / 验收测试 UAT-032 / UAT-033 |
| 建议处理 | 「邮件通知为系统必需能力（关键事件：评论回复、审核结果、被引用），用户可在通知设置中关闭某类邮件；SMTP 库允许引入（nodemailer）」 |
| 决策状态 | ⚠️ 待用户决策 |
| 缓解措施 | 阶段 2 设计前向用户确认；如用户未决策则按建议处理实施，标注为待确认 |

### CONFLICT-002：操作日志「可选」与审计日志「必需」边界不清

| 字段 | 内容 |
|---|---|
| 冲突描述 | NFR-002 原文「操作日志可选」与 NFR-003「敏感操作审计日志」边界冲突：审计日志是否属于操作日志？崩溃重建是否依赖审计日志？操作日志可选是否意味着崩溃后无法重建？ |
| 涉及需求 | NFR-002 / NFR-003 |
| 影响范围 | 可用性 / 安全 / 崩溃恢复 / 验收测试 UAT-042 |
| 建议处理 | 「操作日志 = 写操作 WAL（必需，用于崩溃重建）；审计日志 = 敏感读/写操作记录（必需，不参与崩溃重建，独立存储）」 |
| 决策状态 | ⚠️ 待用户决策 |
| 缓解措施 | 阶段 2 设计明确分层，操作日志覆盖所有写操作；UAT-042 验证重放一致性 |
