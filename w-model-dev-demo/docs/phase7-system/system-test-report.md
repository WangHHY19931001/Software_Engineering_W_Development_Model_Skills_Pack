## 5. 失败用例分析

无失败用例（40/40 通过）。

**契约差异与测试适配说明**（实现契约与阶段 2 设计差异，测试按真实实现断言并在此登记，参照阶段 6 IT-015/IT-026 先例）：

1. **ST-001 JWT 角色快照**：申请博主后，原登录 token 载荷中的 `role` 仍为 `reader`（JWT 为角色快照，不随 userStore 角色变更失效）→ 须重新登录获取博主 JWT 后方可创建文章。与设计"携带 JWT 创建"语义一致（设计前置"获得博主 JWT"）。
2. **ST-002 REPLY 通知对象**：`comment.created` 事件通知对象 = 文章作者（`articleAuthorId`），非设计"回复→被回复人"；博主自回复不产生通知（authorId === articleAuthorId 排除）。与 IT-015 记录一致。
3. **ST-021 博主面板数据隔离**：`GET /api/blogger/stats` 无"他人面板"路径参数，数据按 `token.sub` 取本人（`requireBlogger` 仅校验角色）→ 博主 B 访问得到自己的空面板（数据隔离成立），reader 访问 40301。设计的"他人面板 403"路径在实现中不存在。
4. **ST-013/ST-025 字段与错误码**：详情/列表阅读量字段为 `viewCount`（设计文档 `readCount`）；不存在文章与草稿/归档对读者统一 40402（防枚举语义，接口设计 §0.3 40402 覆盖）。
5. **ST-026 篡改 payload**：JWT 签名完整性保证 payload 篡改必然签名失败 → 40101 TOKEN_INVALID（不重签验证）。
6. **ST-028 按 IP 隔离降级**：supertest 直连 seam 下 `req.ip` 恒为 127.0.0.1（无法模拟多客户端源 IP），"按 IP 独立计数"降级为"按计数键（IP+路径）独立隔离"验证（同一 IP 打满一接口后，其他路径正常响应）。
7. **ST-039 发布事务一致性路径**：设计预期"发布接口 500 + 文章回滚 draft"；实现为事件总线捕获 handler 异常（不阻断主链路，DD-043/ID-4）+ Webhook 异步投递失败记录 → 系统层无部分状态（事件登记与状态变更同链、失败记录落盘、非法发布无事件产生）；存储层进程内事务（快照回滚，NFR-003）经 seam-STORE 验证成立。
