# 博客系统后端 — 需求描述（第 35 轮端到端调测输入）

## 项目背景

构建一个博客系统后端服务（blog-system-demo），为多博主、多读者提供内容发布与消费能力。系统采用 Node.js + Express 4 + TypeScript 5，数据存储使用内存存储（进程内），提供 RESTful API。本轮为 W 模型第 35 轮端到端调测，验证技能包 34.0.0 全部门禁脚本的端到端可用性。

## 业务需求

### 1. 用户与身份
- **用户注册**：读者与博主可注册账号，注册须提供用户名、邮箱、密码；密码须加密存储，邮箱须唯一。
- **用户登录**：注册用户可凭用户名/邮箱 + 密码登录，登录成功后签发 JWT 令牌；令牌有过期时间，过期后须重新登录。
- **博主认证**：注册用户可申请成为博主；博主具备发布文章权限，普通读者无发布权限；仅博主可管理自己的文章。
- **用户资料**：用户可查看和修改自己的资料（昵称、简介、头像 URL）；密码修改须校验原密码。

### 2. 内容发布
- **创建文章**：博主可创建文章，文章包含标题、正文、摘要、标签、分类；创建后状态为草稿。
- **发布文章**：博主可将草稿发布上线，发布后对读者可见；已发布文章可更新（更新后重新发布）。
- **文章状态机**：文章生命周期为 draft → published → archived；已归档文章不可再发布（须先取消归档回 draft）；不可删除已发布文章（仅可归档）。
- **管理文章**：博主可查看文章列表（含草稿与已发布）、编辑文章、删除草稿；删除已发布文章仅可归档。
- **标签管理**：博主可创建标签（名称唯一）、为文章打标签、文章列表按标签筛选。
- **分类管理**：博主可创建分类（名称唯一、可嵌套子分类、深度 ≤ 3 层）、文章归属分类、按分类浏览文章。

### 3. 读者互动
- **浏览文章**：读者可按列表/分页浏览已发布文章，可按分类/标签/关键词搜索文章，可查看文章详情（含正文与作者信息）。
- **评论**：注册用户可对文章发表评论；评论须审核后可见（自动通过）；文章作者可删除自己文章下的评论；评论支持回复。
- **点赞收藏**：注册用户可对文章点赞、收藏；文章详情展示点赞数与收藏数；用户可查看自己的收藏列表。
- **关注博主**：注册用户可关注博主，关注后可在 feed 中看到该博主的新文章；取消关注后不再推送。

### 4. 发现与推荐
- **热门文章**：系统按最近 7 天阅读量排序展示热门文章 Top N（默认 Top 10）。
- **个性化推荐**：系统根据读者阅读历史（标签偏好）推荐相似文章列表；无历史时推荐热门文章。
- **全文搜索**：系统提供按关键词的全文检索（标题 + 正文 + 摘要 + 标签），支持分页与相关性排序。

### 5. 统计与通知
- **阅读统计**：系统记录每篇文章的阅读量，文章详情返回阅读量；阅读量在每次详情访问时 +1（同 IP 短时间窗口去重）。
- **博主统计面板**：博主可查看自己的文章数、总阅读量、总评论数、近 7 天趋势。
- **通知**：系统在用户被回复评论、文章被点赞、关注博主发布新文章时产生通知；用户可查看通知列表并标记已读。

### 6. 订阅与集成
- **RSS 订阅**：系统为每个博主提供 RSS 源（文章标题/链接/摘要/发布时间）；读者可订阅 RSS。
- **Webhook**：系统在文章发布、评论新增时触发 Webhook 回调（URL 由博主配置），回调带事件签名，失败自动重试 3 次。

## 非功能需求

- **性能**：常规 API 响应时间 P95 ≤ 200ms（生产目标）；单接口在测试环境基线 ≤ 2000ms。
- **安全**：密码存储使用 bcrypt 加盐哈希；JWT 密钥通过环境变量注入，不得硬编码；API 请求须校验 JWT 有效性。
- **可靠性**：系统关键操作（文章发布、Webhook 回调）具备重试与失败记录；单点故障不导致数据丢失（内存存储下以进程内事务保证一致性）。
- **代码质量**：单元测试代码行覆盖率 ≥ 80%。
- **可维护性**：代码模块化分层（路由/服务/存储），命名遵循领域术语，禁止跨模块直接访问存储实例。
- **API 限流**：认证接口（登录/注册）限流 10 次/分钟/IP；通用 API 限流 100 次/分钟/IP，超限返回 429。

## 约束需求

- **技术栈约束**：后端仅使用 Node.js + Express 4 + TypeScript 5；存储为内存实现；不得引入外部数据库。
- **接口契约**：全部接口采用 RESTful 风格，JSON 请求/响应；错误响应统一结构 `{ error: { code, message } }`。
- **认证约束**：JWT 令牌有效期 24 小时；密钥由环境变量 `JWT_SECRET` 注入；测试环境使用注入的测试密钥。
- **审计日志保留**：关键操作（登录、发布、删除）须记录审计日志，日志保留至少 90 天。

## 明确的 Out of Scope（边界场景，供 S 子代理核对）

- 前端页面/管理后台（本轮仅后端 API）
- 图片/附件上传存储
- 多租户隔离（单系统实例）
- 消息推送（移动端推送通道）
- 付费订阅 / 广告系统

## 验收测试设计要求（同步产出）

- 每个功能需求至少设计 2 条验收测试用例（正常 + 异常/边界）
- 每个非功能需求设计 1-2 条验收测试用例（性能/安全/可靠性/质量/可维护性/限流）
- 每个约束需求设计 1 条验收测试用例
- 每条验收测试用例须包含前置条件分析（认证状态 / 数据依赖 / 接口路径）
- 预期验收测试用例总量约 60~80 条（UAT-NNN 编号）
