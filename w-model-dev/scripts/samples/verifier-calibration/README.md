# Verifier 校准集（**非门禁**）

> **边界声明（最重要的一条）**：本目录**不是门禁**。没有脚本读取它，没有 CI 项依赖它，
> 没有任何阶段门 / 质量门 / 自检基线因它而红。锚定正解由**人工标注**，且校准需**真实运行 LLM**
> （由外部 Agent 执行）——两者都不符合「确定性门禁」的定义。把它当成门禁即为**过度声明**。
> 后续维护者不得把它当作可阻断流程的检查项，也不得因它「未接入 CI」而判定其失效
> （措辞与 [verifier-spec.md §14.4](../../../references/verifier-spec.md) 一致）。
>
> 想要把它**升级成门禁**必须走一次独立的设计决策（SSoT 先行），不得由本目录的 README 单独授权。

## 用途

发现 V 评审的**校准偏移**：V 的分辨力下降——正样本与负样本都被判高分，或两者都挤在中段，
即评审者打了分但**没有区分正负样本的能力**。这与「标准偏移」（同一产物跨轮次判出差异显著的
等级，R9）和「惰性偏移」（评审敷衍，R11/R12）是三类不同的失效，详见
[verifier-spec.md §14](../../../references/verifier-spec.md)。

本目录提供**带人工标注正解的锚定样本**：论文度量评审判别力需要 ground truth，而这里是仓库内
唯一可以安放这类正解的地方（见仓库 `docs/superpowers/specs/2026-09-12-gate-integrity-and-evidence-denominator-design.md` §2.8）。

**论文依据**：arXiv:2607.05391 Table 1 显示粒度上升 → 正负样本分离 SNR 上升；标准 judge 在
100 次重复中 **88 次产生平局**——分辨力不足是真实且可测量的失效模式，不是理论担忧。
论文**支持校准集的价值**，但**不改变其非门禁性质**；不得表述为「论文为门禁背书」。

## 样本格式

每个样本是 JSON。两种形态，共用两个校准标注字段：

- `expectedVerdict`（人工标注）：本样本**应当**被如何判定，取值见下表。
- `expectedRationale`（人工标注）：**为什么**是这个正解——供复核标注本身是否正确，
  让标注可审计而不是一句断言。

**形态 A：VerifierOutput 锚定样本**（单轮评审，检验 R18 分辨力下限）

主体是标准 `VerifierOutput` 形状（[verifier-output.schema.json](../../../schemas/verifier-output.schema.json)），
外加上述两个标注字段：

- `expectedVerdict: "pass"` —— 评审者分辨力正常，不该被 R18 报。
- `expectedVerdict: "flagged"` —— 该样本命中某条漂移判据（`expectedRule` 声明是哪条）。

**形态 B：跨轮次 run-log 锚定样本**（多轮评审，检验 R9 标准偏移）

主体是 `runLogEntries` 数组（标准 run-log 条目），外加两个标注字段：

- `expectedVerdict: "flagged"` —— 同一产物跨轮次质量等级差 ≥2 档，命中 R9。
- `expectedVerdict: "not-flagged"` —— 不命中（含**首次评审豁免**：仅一次评审无「不一致」可言）。

每个样本另有 `sampleId` / `calibrationTarget`（`R18` / `R9`）/ `expectedRule` 字段，
便于校准脚本按判据分组统计。

## 校准方式

**可选、非门禁**的命令（不在 `self-test.ts`，不在任何 `check-*.ts`）：

1. 逐样本读入，按形态分派：
   - 形态 A → `checkVerifierOutput(sample)`（`logic/verifier-logic.ts`），检查 `reasons` 中是否出现
     R18 记录、`passed` 是否与预期一致。
   - 形态 B → `checkRunLog(sample.runLogEntries)`（`logic/run-log-logic.ts`），检查 `violations`
     中是否出现 R9 记录。
2. 比对**实际判定**与人工 `expectedVerdict`，输出**校准报告**：命中率 + 混淆矩阵
   （预期 pass / flagged × 实际 pass / flagged）。
3. **一致**→ 校准通过；**不一致 → 是发现，不是错误**。差异应报告而非改标注去迎合实现：
   要么实现有缺陷（假阳性 / 假阴性），要么人工标注本身错了，两者都值得人看。

> 校准报告**只输出**，不产生 `exitCode`，不阻断任何流程。校准是一次**离线诊断**，
> 不是 CI 检查项。

### 为什么阈值能廉价校准

`RESOLUTION_FLOOR`（`verifier-logic.ts`）、`REVIEW_LEVEL_SPREAD`（`run-log-logic.ts`）等阈值
均为**导出常量**且**先行取值**，端到端调测后校准（规格 D23）。校准集正是该次校准的度量基准：
若校准显示某阈值假阳性/假阴性偏高，改常量即可，无需改动判据结构。

**取值教训（实测，勿回退）**：`RESOLUTION_FLOOR` 初版按设计直觉取 `1e-4`，实测会命中**全部**
合法 V 产物（仓库内合法 fixture 的实测方差一律 `6.67e-5`，**高于** `1e-4`），即「计划里的代码
片段只是意图草图」的实例。现取 `1e-6`，两侧各留约两个数量级余量。校准若发现该值需要调整，
必须**基于实测重算**而非设计期估算。

### 入库时的实测基线（2026-09-13）

本校准集在入库时已**实际跑过真实逻辑层**（非纸面推演），6/6 与人工标注一致，
每条样本除被测判据外**无其它违规**（干净锚点，归因唯一）：

| 样本                              | 判据 | 人工标注    | 实测判定    | 实测归因                                    |
| --------------------------------- | ---- | ----------- | ----------- | ------------------------------------------- |
| `resolution-spread-001.json`      | R18  | pass        | pass        | 无（假阳性防护侧）                          |
| `resolution-collapse-001.json`    | R18  | flagged     | flagged     | R18（方差 6.67e-9 < 1e-6）                  |
| `resolution-exact-equal-001.json` | R18  | flagged     | flagged     | 防漂移规则 1（**R18 返回 `[]`，不重复报**） |
| `review-drift-spread2-001.json`   | R9   | flagged     | flagged     | R9（A→C 跨 2 档）                           |
| `review-first-only-001.json`      | R9   | not-flagged | not-flagged | 无（首次评审豁免）                          |
| `review-spread1-001.json`         | R9   | not-flagged | not-flagged | 无（A→B 跨 1 档 < 2，正常改进）             |

> 上表是**入库时**的观测快照。后续阈值调整或实现变更后重跑，若出现不一致，**以实测定论并作为
> 发现上报**——不得为了让表继续保持绿色而改人工标注。

## 已知漂移面

**本校准集自身也会漂移**，登记如下（对应设计规格 §5 的已知风险）：

| 漂移面                       | 表现                                                                                       | 处置                                                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| **人工标注本身会过时**       | 产物形态变化、评审标准修订后，`expectedVerdict` 可能不再成立——标注冻结的是**当时**的正解   | 校准报告能**暴露**漂移（命中率骤降）但不阻断流程；标注维护责任登记于此，需人工复核 `expectedRationale` 是否仍成立 |
| **阈值是先行取值**           | `RESOLUTION_FLOOR=1e-6` / `REVIEW_LEVEL_SPREAD=2` 均为端到端调测前的保守取值，非实测收敛值 | 数值以**代码常量为权威**（本目录与 verifier-spec 均不复制数值）；校准后由 D23 一次性收敛                          |
| **样本数与覆盖面有限**       | 少量锚定样本只覆盖**已识别**的失效模式（R18/R9），不构成统计意义上的判别力估计             | 样本集刻意保持小而精（5–8 条）；新增样本须带可审计的 `expectedRationale`，不得机械堆量                            |
| **「校准通过」不代表无漂移** | 样本全绿只说明 V 在这几条锚定样本上判别力正常，**不等于** V 在任意真实产物上都不漂移       | 校准是**信号**不是证明；不得据此声称评审质量已保证                                                                |
| **模型/提示词版本变化**      | 更换 V 使用的模型或 Persona 提示词后，历史校准结论不再适用                                 | 版本变更后须重跑校准，不得沿用旧命中率                                                                            |

> **不得过度声明**：校准集既不阻断流程，也不证明评审无漂移。它是**离线诊断工具**——
> 用来观察 V 是否漂移、阈值是否需要调整。把它说成门禁或质量保证即为过度声明。
