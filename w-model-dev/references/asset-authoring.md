## 1. 适用范围与自我适用

本文约束技能资产（`SKILL.md` / `references/` / `templates/`）的**编写与评审**。写或评审任一技能资产前读本文；V 子代理评审技能资产时，按本文给出可执行的改进项。

本文自身也是技能资产，因此**自我适用**：第 5 节的数字阈值与第 10–12 节的修剪纪律同样约束本文件；本文件规模、目录、引用深度均由文末自检清单自证。

## 2. 两种负载：context load 与 cognitive load

每新增一份文档或一个指针，都在花两种预算之一：

- **context load（上下文负载）**：常驻 agent 上下文窗口的成本——`AGENTS.md` 的一行、技能 description、任何每轮都占着 token 与注意力的东西，无论是否触发都在付费。
- **cognitive load（认知负载）**：落在人身上的成本——有哪些文档、何时该去够哪一份；**人是索引**。它不是要最小化的成本，而是人的自主性的代价：在人判断有价值处花费，在人判断无价值处移除。

只经指针到达的材料，以「指针自身一行」的代价免除 context load；完全没有指针的材料，全部负载压在 cognitive load 上。

## 3. 信息层级阶梯

文档由两类内容构成：**steps**（agent 按序执行的动作）与 **reference**（按需查阅的定义、规则、事实）。两者自由混合：全 steps（一份配方）、全 reference（一套评审规则、本文件）、或两者兼有。核心决策是每块内容坐在**信息层级阶梯**的哪一级——阶梯按「agent 多急需该材料」排序：

1. **in-file step**：主层，agent 要按序做的事。
2. **in-file reference**：按需查阅，常是合法的**扁平同级集合**（一套评审规则同处一梯），是合理排布而非坏味道。
3. **disclosed reference**：推出到独立文件，经上下文指针到达，指针触发时才加载；范围从同目录兄弟文件一直到完全外部的任意文档。

## 4. 渐进披露判据（分支判据）

**渐进披露（progressive disclosure）** 是沿阶梯下移（移出主文件、放到指针之后），让顶层保持可读。它的首要目的不是省 token，而是保护层级本身。

推得太少，顶部臃肿；推得太多，藏起 agent 真正需要的材料。这个张力就是全部决策。

最干净的披露判据是**分支**：每个分支都要的**内联**；只有部分分支到达的**推到指针之后**。当文档有 steps 时，本应被披露却仍留在文件内的 reference 会掩埋步骤，把「是否处理这些步骤」变成抛硬币——这是方差杠杆，不只是可读性杠杆。

## 5. 数字阈值（S03 权威数值）

以下数字是本仓库的**权威阈值**，本节即其单一权威位置：

| 对象 | 阈值 |
|---|---|
| `SKILL.md` body | < 500 行；接近上限即拆出独立文件 |
| 100+ 行的重参考内容 | 须落到独立文件（重参考：API 文档、完整语法等） |
| 代码 / 内容 | < 50 行保持内联 |
| 引用深度（**新增**参考文件） | **只允许一层深**：新增参考文件须能由 `SKILL.md` 直接链接；既有 2 跳文件按下述例外处理 |
| 参考文件目录 | > 100 行的参考文件在顶部加**目录（TOC）** |
| getting-started 工作流 | < 150 词 / 篇 |
| 高频加载技能 | < 200 词总计 |
| 其他技能 | < 500 词（仍须简洁） |

引用只能一层深的原则（源自 S03）：嵌套引用会让 agent 用 `head -100` 之类命令**预读**而非完整读文件，得到不完整的信息；> 100 行的参考文件加 TOC，正是让 agent 局部预读时也能看到全文范围。

**本仓库的例外与偏离理由**：既有 `references/` 中有 **11 个"2 跳"文件**（`command-reference` / `concurrency-guide` / `conventions` / `data-models` / `event-ingress-guide` / `hill-climbing-guide` / `iceberg-sweep-guide` / `root-cause-locator` / `signature-chain-guide` / `skillopt-adoption` / `workflow`），需经其上游文件（如 `hard-constraints` / `phase-N` / `subagent-delegation`）间接引用才可达；其权威清单与定级见 `subagent-delegation.md` §3.1「全 references 触发条件表」。这些文件按**既定例外**处理：经上游文件间接可达，且由**编排者按触发表显式加载**（不做嵌套预读）。故「只允许一层深」**只对新增参考文件生效**；本仓库偏离该一层深原则的理由是：按需加载由编排者按触发表触发，加载是**显式动作**而非"读到引用才去够"，`head -100` 式部分读取的风险因此不适用。

## 6. 跨文件 / 跨角色引用约定

引用按**适用范围**分流：

**跨技能（引用其他 skill 包）**——用**显式要求标记**，而非含糊的「参见」：

- `**REQUIRED SUB-SKILL:**` —— 我（agent）必须调用或加载的其他技能。
- `**REQUIRED BACKGROUND:**` —— 我必须先理解的前置材料。
- 反例：`参见 skills/xxx`——读者无法判定它是不是必须。

这类标记的用途是**区分「必须加载」与「可选参考」**：跨技能引用拿不到技能上下文，只有显式标记才能让 agent 判定该目标是否强制。

**技能包内文件互引用**——**沿用既有 Markdown 相对链接**（本仓库 `SKILL.md` 与 `references/` 的既有做法，即以 Markdown 相对链接互指同目录文件），**不**要求引入 `REQUIRED SUB-SKILL` 标记：包内文件同属一个技能，读者已在技能上下文中，同目录相对链接已能无歧义地指向目标；给包内引用套显式要求标记只会制造一套全仓并不遵守的形式。

**禁止 `@` 深链**：`@` 语法立即强加载目标文件，在任何需要它之前就烧掉 200k+ 上下文。跨技能引用统一写成「技能名 + 显式要求标记」；包内引用写成 Markdown 相对链接。

## 7. 指针措辞（context pointer）

**上下文指针（context pointer）** 是常驻 agent 上下文中的一个引用：它命名某个不在上下文里的材料，并编码「何时到达它」的条件。技能 description 是一个指针；`AGENTS.md` 里命名某文档的一行也是同一对象。

决定 agent 何时到达该材料、以及到达是否可靠的，是**指针的措辞**，而不是它的目标。**必须有的目标 + 弱措辞的指针 = 方差缺陷**：先磨措辞，磨不动才把材料内联。

三条剪枝：

1. **leading word 前置**——指针正是指挥该词触发的地方。
2. **每分支只留一个触发**——同义改写是在把同一分支写两遍；合并，只留真正不同的分支。
3. **删掉正文已承载的身份**——正文已说明「这是什么」时，指针不必重复。

## 8. leading word

**leading word** 是已经活在模型预训练里的紧凑概念，agent 运行文档时用它思考（如 _lesson_、_fog of war_、_tracer bullets_）。它以 **token 重复**而非句子重复出现，累积出分布式定义，用最少 token 招募模型既有的先验，锚住一整片行为。

自造词不招募先验：预训练词免费给出的东西，自造词要用定义 token 付费。**优先用既有词**。

它锚定两次：正文里锚 **execution**——同一个词每次出现都指向同一行为，在扁平 reference 里聚焦「要盯的一类东西」；指针里锚 **invocation**——同一个词同时活在提示词、文档与代码库里，agent 把共享语言链接到材料，到达更可靠。

把一段话收成一个词的两个范例：

- 「fast, deterministic, low-overhead」→ _tight_（a _tight_ loop）。
- 「a loop you believe in」→ _red_：把模糊门变成二值可观测状态（循环在 bug 上变 _red_，或不变）。

收获两倍：token 更少，且给 agent 一个更锐利的思考挂钩。假定每份文档都在携带可被 leading word 退休的复述，去找它们。

## 9. 完成判据（completion criterion）与 premature completion 防御顺序

每个 step 以**完成判据**收尾——告诉 agent 工作做完的条件。两个属性使它成为杠杆：

- **clarity（清晰度）**：agent 能否区分「做完了」与「没做完」？含糊的界（如「达成理解」）会诱发 **premature completion**：在真正做完之前结束该步，注意力滑向「已做完」。前方可见的后续步骤（post-completion steps）提供拉力，判据的清晰度是阻力。
- **demand（要求量）**：要求多少。「每一个被修改的 model 都要交代」强制彻底工作，「产出一份变更清单」则不能。demand 驱动 **legwork**——agent 在工作内自行挖掘的功夫，潜藏在措辞里而不是写成一个独立步骤；且它不受 step 边界约束：「每条规则都已应用」同样能约束一堆扁平 reference，这正是全 reference 文档也能携带穷尽要求的原因。

防御**按序**：先磨界（局部且便宜）；只有当界**不可约地模糊**且**观察到抢工**时，才用「拆序列、把后续步骤藏起来」。而「藏」只在**真实上下文边界**（交接或子代理分派，见 [subagent-delegation.md](subagent-delegation.md)）上有效——内联调用不会清理任何东西，后续步骤仍留在上下文里。

最强判据同时**可核对**且**穷尽**。

## 10. co-location

信息层级阶梯决定一块内容**放多深**；**co-location** 决定它到了之后**旁边放什么**。把一个概念的**定义 / 规则 / 注意事项放在同一标题下**，而非散落各处，使读一部分就带出它的邻居。

判据：文档应当读起来像「为 agent 写的文档」。成组的材料这样读；散落的材料不这样读。

与 duplication 不同：**duplication 把一个含义写在两处；scattering 把一个含义碎在多处**。

## 11. pruning 四刀

**第一刀：单一事实源（single source of truth）。** 一个含义一个权威位置，改行为是一处编辑。**duplication**（同一含义在多处）花费维护与 token，并把该含义在阶梯上的显眼度抬过它真实的排位。它恰是 leading word 的反面——后者**故意重复 token，从不重复含义**。

**第二刀：环境也是事实源。** `package.json` scripts、配置文件、目录布局、`--help` 输出都是事实源；文档复述它们即**缓存**——一次查询的拷贝，只有查询昂贵时才配得上它的负载。缓存那些「看也看不出的约定、选择背后的理由、没有配置会承认的坑」；一文件一命令就能查到的，留给环境，免得过期。

**第三刀：relevance（相关性）。** 每一行是否仍与这份文档要做的事相关？一行失去相关性有两条路：从不相关（纯说明、或本应披露的分支），或过期（它描述的行为/世界已变）。更短的文档更容易保持相关。没有修剪纪律，默认归宿是 **sediment**：因为「加安全、删危险」而沉积的过期层，直到你必须像取芯一样钻透它们，才能找到还活着的东西。

**第四刀：逐句猎 no-op**（判据见第 12 节）。

## 12. no-op test（可观测判据）

判据是**行为性**的：「删掉这一行，agent 的行为是否改变？」模型默认就会遵守的指令，付了负载却什么也没说。

该判据是**模型相对**的，不是读者相对的：两个人对 no-op 有分歧，其实是两人对「默认行为」有分歧；用**跑文档**（拿真实 agent 观察行为）而不是辩论来裁定。

某句不过关时，**删整句**，而不是从句子里修剪词。

该测试同样给 leading word 评级：弱到打不过默认的词（agent 本已 thorough-ish 时写 _be thorough_）就是 no-op；修法是换**更强的词**（_relentless_），不是换技术。

## 13. 授权不写（no-guidance control，S04）

这是行为塑造类指引的**准入闸**：写之前先取一个**不写该指引的对照**。

**如果对照没有表现出该失败，就没有要修的东西——停下，不要写这条指引。**

已完成的行为塑造类指引还须做措辞微测：**≥ 5 次重复**，且**每一条被判命中的匹配都人工读过**。纯 reference 类技能不适用本条（本条只管行为塑造，不管按需查阅的参考材料）。

## 14. 自检清单

写或评审技能资产后，逐项核对：

- [ ] **数字阈值**：`SKILL.md` body < 500 行；没有 > 100 行仍留在主文件的参考材料；< 50 行的代码/内容保持内联；**新增**参考文件引用只有一层深（既有 2 跳文件按 §5 例外处理）；> 100 行的参考文件已在顶部加目录；词数满足 < 150 / < 200 / < 500。
- [ ] **指针**：每个指针都有清晰措辞与**单一触发**（分支已合并，无同义改写重复）；必须有的目标没有配弱措辞。
- [ ] **no-op test**：逐句问过「删掉它，agent 行为是否改变」；不过关的整句已删，弱 leading word 已换成更强的词。
- [ ] **sediment**：没有因「加安全、删危险」而沉积的过期层；环境已有的事实没有被缓存成文档复述。
- [ ] **co-location**：一个概念的定义 / 规则 / 注意事项在同一标题下，未散落多处、也未重复多处。
- [ ] **行为塑造类指引**：取过不写该指引的对照；对照未复现失败的一律停下、未写；已写出的做过 ≥ 5 次措辞微测。
- [ ] **跨技能引用**：引用其他 skill 包时使用 `**REQUIRED SUB-SKILL:**` / `**REQUIRED BACKGROUND:**` 显式标记（包内文件互引用沿用 Markdown 相对链接，不套显式要求标记）；任何位置均未使用 `@` 深链。
