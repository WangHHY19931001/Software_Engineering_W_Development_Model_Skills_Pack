# 并发编程指南（Concurrency Guide）

> 提炼自《代码整洁之道》ch13 + 附录 A（并发编程 II）。
> 用途：阶段 5 编码涉及并发/多线程/异步代码时，S-coding 自检 + V-code 评审按此检查。
> 检查双轨：机械规则（同步区大小、共享可变状态声明）由语言静态工具扫描；语义判断（竞态/死锁风险）由 V 子代理 LLM 评审。

## 并发防御三原则

1. **并发代码独立成类**（SRP）：并发相关逻辑单独封装，不混入业务类。
2. **限制共享数据作用域**：共享可变状态范围越小越好；优先使用数据副本/不可变数据。
3. **线程尽量独立**：减少线程间协作点；协作点越少，竞态窗口越小。

## 同步区纪律

- **同步区尽量小**：锁只保护临界资源，不做无关计算；持锁时间越短，死锁/争用概率越低。
- **警惕同一共享对象上的多个同步方法的组合依赖**：client/server/adapted 三种加锁策略中，推荐 server-based（对象内部方法级同步，调用方无需理解锁语义）。

## 死锁四条件（apA）

死锁成立须同时满足四条件，打破任一即可防死锁：

| 条件 | 含义 | 破局手段 |
|---|---|---|
| 互斥 | 资源一次只能一个线程使用 | 用不可变数据/副本替代 |
| 持有并等待 | 持有一资源等待另一资源 | 一次性申请全部资源 |
| 不可抢占 | 已获资源不能被强制夺走 | 超时释放/可中断锁 |
| 循环等待 | 线程间形成等待环 | 全序锁顺序（按固定顺序加锁） |

## 测试线程代码

- **偶发失败先当线程问题**：禁止归咎"one-off"；先单线程跑通，再多线程重复跑。
- **线程数 > 处理器数**：放大竞争暴露竞态。
- **多平台重复跑**：调度器差异可暴露时序 bug。
- **插桩逼出竞态**：jiggle 随机扰动 / ConTest 类工具主动打乱时序。

## 条件等待

> 与上节互补：上节管「测试线程代码怎么写」（单线程先跑通、多线程重复跑、插桩逼出竞态），本节管「断言前的等待怎么写」——等真实条件成立，不赌时长。

**三要素**（缺一即埋下偶发不稳定）：

| # | 要素 | 该做 | 不该做 |
|---|---|---|---|
| 1 | 先等触发条件 | 显式等待被测条件本身成立（条件轮询、事件/回调、信号量、`waitFor` 谓词） | `await sleep(500)` 赌 500ms 够用；等待与要断言的条件无关 |
| 2 | 基于已知节奏而非猜测 | 等待上限来自被测系统的已知节奏（已约定的超时/重试间隔/退避上限），并写明依据 | 拍脑袋写 `sleep(1000)`；偶发没过就把时长再放大一倍 |
| 3 | 注释说明原因 | 等待处注明「等什么条件、为何是这个上限」，使后来者可判定该依据是否仍成立 | 静默 `sleep` 不写原因，后人只能继续加时长 |

**三反模式**：

| 反模式 | 为什么错 | 改成什么 |
|---|---|---|
| 轮询过快 | 间隔小于被测条件的推进粒度，空转消耗 CPU 且放大调度噪声，仍可能错过时序窗口 | 间隔对齐被测节奏（事件驱动优先于轮询）；必要时退避而非固定高频 |
| 无 timeout | 条件永不成立时无限等待，进程挂死而非快速给出可诊断信号 | 每个等待显式带上限；超时输出「等了什么条件、实际观测到什么」再判不通过 |
| getter 在循环外取陈旧数据 | 循环外只取一次值并复用，循环内读的是不会再更新的副本，等待的是个不变量，永远看不到变化 | getter 放进循环/谓词内每次重新取值——等待的对象必须是每次重新读取的实时值 |

**边界（防误读）**：本节规范的是**断言前的等待**（测试断言与生产代码中的等待同此纪律），**不禁止一切 sleep**。为**提高复现率**而注入 sleep（循环 100×、加压、收窄时序窗，见 `root-cause-locator.md` §2.8「S 侧 loop 构造方法清单」）是**另一用途**：那里的 sleep 服务于把低复现率 flake 抬到可调试，与本节规范的等待纪律用途不同，两者不冲突，且**不得互相援引**（不得以复现率注入为由违反本节，也不得以本节为由否决提高复现率的注入）。

## 静态工具 + LLM 评审双轨

- **机械规则**：同步区大小 / 共享可变状态声明 → 语言静态工具（TS: eslint 相关 rule；Java: SpotBugs/PMD 并发规则；Go: go vet -copylocks）。
- **语义判断**：竞态窗口 / 死锁可能 / 组合依赖 → V-code 评审按上表逐条 LLM 检查，命中项标注分级写入 reworkHints。
