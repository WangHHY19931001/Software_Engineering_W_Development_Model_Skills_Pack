# 估算纪律（Estimation Guide）

> 吸收自《agent 时代的人月神话》第 8 章：编码份额趋近零——"五分钟是编码，一小时×3 是其他工序"。
> 吸收决策见 `docs/changes/decision-log/absorptions.md`「人月神话吸收」；本文件为可执行细则。
> 强制等级：违反本文件「禁外推」规则属估算失实（与约束 #4『真实执行』同族）。

## 禁"编码×系数"外推

- 编码份额趋近零："让 agent 写这段代码要多久"不是可估的问题——编码只占总工序的一小块。
- 估"完全搞清楚这段代码应该做什么并验证做对了要多久"，不估"让 agent 写这段代码要多久"。
- 任何按"编码耗时 × 系数"外推总工期的估算一律标记不可靠。

## mini-spike 前置

- 正式估算前跑一段真实小片段（成本几十美分，节省误差可能数周）。
- "我不知道，我们跑一小段真实工作试试看"是最诚实的估算。
- mini-spike 产物可弃，学到的结论记入决策记录（见记账模板）。

## 记账模板

每周几分钟录入，一年后是自己的估算基线：

| 字段 | 说明 |
|---|---|
| 任务名 | 可检索的名称 |
| 开始时间 | 本次工作开始 |
| 结束时间 | 本次工作结束 |
| agent 用量 | token 或费用 |
| 你的判断内容 | 简短几句（判断依据 / 中间结论） |
| 结果 | 实际产出 / 是否达标 |

## 玩具外推警戒

凡"看到 demo 做 X → 估我做 Y 也这个时间"一律标记不可靠：demo 的复杂度、边界与你的任务不在同一量级。

## 模型档位 × 思考预算

> 吸收自 Agentic Design Patterns ch17「推理扩展定律」：性能 = 模型大小 × 推理计算投入；给更小模型更多"思考预算"可超越更大模型。

- **预算权衡判据**：任务超出当前模型档位能力时，先评估"增加思考轮次/反思预算"（成本可控）vs "换更大模型"（成本跃升）——小模型 + 多轮反思常是更优成本决策。
- **估入预算**：多轮反思/自我修正会显著增加 token 消耗，须计入估算（见记账模板 agent 用量字段）。
- **不臆测档位**：模型档位选择与预算决策记入估算依据；不得静默降档换量。

## 模型档位 × 修复轮次 escalation

> 「不臆测档位」（上节）要求档位决策**被写下并记入估算依据**；本节给出写下时的判据。两者不冲突：**显式指定档位 ≠ 臆测档位**——臆测是「没说、没记、悄悄换」，显式指定是「说清档位、写下判据、记入估算依据」。

**按角色/任务定档（用能胜任该角色的最省档位，省成本且更快）：**

- **机械实现任务**（孤立函数、规格明确、1-2 个文件）→ 快而便宜的档位。计划写得足够细时，多数实现任务都是机械任务。
- **集成与判断任务**（多文件协调、模式匹配、调试）→ 标准档位。
- **架构与设计任务** → 当前可用的最强档位。**整分支终审属于这一类**：它必须用最强档位分派，而不是用会话默认档位。

**评审任务**：按 diff 的规模、复杂度与风险选同等判断力的档位——小而机械的 diff 不需要最强档位，细微的并发改动则需要。**小 fix delta 的 scoped re-review（见 `subagent-delegation.md` §3.4.2）可用便宜到中档**。但**中档是评审者与「按散文描述实施」的实现者的下限**：最便宜的档位在多步任务上常要多花 2-3 倍回合数，回合数（墙钟与上下文成本）比 token 单价更决定总成本。**当计划文本已含要写的完整代码时**，实施退化为「誊写 + 测试」，该实现者与单文件机械修复一样可取最便宜档位。

**修复轮次 escalation（4-5 轮）**：修复轮次进入 **4-5 轮**时，修复分派须使用**至少比卡住的那个实现者高一档**的模型。**（本仓库扩展）** 台账该条只针对**修复**分派；本仓库把**同轮评审**一并纳入升级对象（三个分派模板口径一致：V / R / S-fix）——评审与修复同轮同档，否则固定的评审档位会成为升级后的瓶颈。（以下为本仓库的阐释性理由，非台账规则：同一档位重复失败说明该档位解不开这个结，继续同档只是重跑。）

**必须显式指定模型**：分派子代理时**始终显式写出模型档位**。省略模型 = 子代理静默继承编排者会话的模型（常是最强、最贵的档位），本节全部判据随之失效——这是**静默摧毁本节**的方式。档位一行与判据一并记入估算依据（记账模板「你的判断内容」字段），与「不臆测档位」同源：档位是**写下来的决策**，不是默认继承的副作用。
